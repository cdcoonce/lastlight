# Observed contrasts: bands in pixel rows above the frozen skyline

**Decided:** `lastlight observe` turns an evening's saved WHTM1 frames into `observed.json` (issue #17, as amended by the conductor's spec change of 2026-10-11). Each frame becomes a **within-frame contrast profile over bands of pixel rows above the camera's frozen skyline**, differenced against a reference band of the same frame, so the camera's per-channel exposure and white balance cancel. `lastlight.observe.contrast_profile` does the pixel work, `lastlight.observe.bands` checks a camera's bands against its frozen fit, `lastlight.observe.evening` runs a whole evening, `lastlight.commands.observe` is the thin command, and `vividness_v0` is a named placeholder.

- **Bands are rows, per camera, in the registry.** `[camera.contrast]` in `registry.toml` holds `skyline_margin_rows`, `bands_rows` (half-open `[lo, hi)` offsets above the skyline), `reference_rows` and `light_dome_columns`. WHTM1 is seeded with margin 8, bands `[8,28) [28,48) [48,68) [68,88) [88,108)` and reference `[118,138)`, as the conductor specified. ESMO1 has no frozen fit, so it has no table, and `observe --camera ESMO1` exits 2 and says so.
- **A band is `d` rows above a column's own skyline.** The skyline row of a column is the fitted curve rounded half up to a whole row; the band `[lo, hi)` is the rows `skyline - d` for `d` from `lo` to `hi - 1`. Whole rows make the definition identical in every frame and under any refit that leaves the skyline in place. The band's pixel set is therefore exact; only the label `view_elevation_deg` (nominal, with a `range` from the fit's `uncertainty.px_per_deg`) depends on the pixel scale, and `observed.json` says it is nominal.
- **What counts.** Decode, linearise with the sRGB transfer function, drop pixels with any channel at or above 250 (saturated) or every channel at or below 5, or any channel at 0 (its log is undefined; counted as too dark). Per band, the median of `log(R/G)` and of `log(B/G)`; the contrast is the band's median minus the reference band's. A band with fewer than 50 valid pixels is missing (`null`, with the reason), and so is every contrast when the reference is. Nothing is filled.
- **Exclusions are counted, in four disjoint buckets** (`geometry`, `light_dome`, `saturated`, `too_dark`; a pixel is charged to the first that applies). With the valid pixels they add up to the band's nominal size, 20 rows times 800 columns, and the tests check each bucket against a frame built to hit only that bucket, not just the sum. A column in which the whole band is not inside the frame and the sky mask is left out of that band as `geometry`, never clipped to a partial band, so a band always means the same rows.
- **The window and the sun.** Each frame's instant is read from its file name with the collector's own reader (`camgeom.frames.parse_frame_time`, the inverse of `archive.frame_stem`; a test round-trips them), and the sun's elevation is computed with `lastlight.geometry` at the camera's registry position. A sidecar is never consulted. Frames are kept with the sun between +6 and -6 degrees by default (`--min-sun-elev`, `--max-sun-elev` override), the edges inclusive. Every frame not kept is counted by reason (`no_time_in_name`, `unreadable`, `wrong_size`, `sun_above_window`, `sun_below_window`), and all five reasons are always in the file, zero or not.
- **`observed.json` names the geometry it used**: the SHA-256 of the frozen fit file and its `provisional` flag. It echoes the band definition, so the file describes itself, and it carries per frame a 12 character SHA-256 prefix and the sun elevation to two decimals, nothing else that identifies a frame. No file name, no time, no pixel, no coordinate. The tests run the repository's own privacy scanner over a written file and check the structure (no list longer than 12 items, no long string but the two sentences the file carries).
- **Exit codes**: 0 written with at least one frame; 1 no usable frame (the file is still written, with every drop counted, so the evening is on the record: honesty rule 5); 2 bad input or configuration (unknown camera, no contrast table, no frozen fit, a table that does not fit the fit, no archive folder for the evening, an empty window).
- **`vividness_v0(profile_series)`** is the maximum over frames of the lowest band's `log_rg` contrast, `None` when no frame has one. It is named a placeholder in its docstring and by `VIVIDNESS_V0_RULE`; the pre-registered definition (`docs/gates/vividness.md`) is still due. Nothing seals or scores it yet, and it is deliberately not in `observed.json`. It shares a name with `lastlight.vividness.vividness_v0`, the forecast's placeholder, which has another signature; the two modules never import each other.

**The bands against the frozen fit.** `validate_contrast` loads the frozen `WHTM1.json` and requires every band and the reference to lie wholly inside the fit's sky mask (`camgeom.mask.sky_mask_rows`: margin in rows, overlay boxes out, skyline seen) in at least 95 percent of columns. The skyline runs from row 145.5 to 194.2, so the topmost row any band touches is row 9 (in the highest column, 137 rows above row 146), and nothing leaves the frame:

| Band (rows above skyline) | Columns inside the sky mask |
| --- | --- |
| 8 to 28 | 800 of 800 (100 percent) |
| 28 to 48 | 800 of 800 |
| 48 to 68 | 800 of 800 |
| 68 to 88 | 800 of 800 |
| 88 to 108 | 800 of 800 |
| reference 118 to 138 | 800 of 800 |

The reference was not moved: the conductor's rule moves it down in 10-row steps only if needed. For the record, the next two steps up would have given 98.8 percent (128 to 148) and 79.4 percent (138 to 158), so the rule has teeth on this fit, and a test pins that a reference 50 rows higher is refused. `observe` runs this check before it reads a frame; a refit that moves the skyline cannot quietly leave a band off the top of the frame.

**How the light-dome columns were chosen (WHTM1: columns 530 to 799).** The only frames of the first evening with the sun below -6 are one (at -7.05 degrees by the registry position), so the seed rests on that frame and one more at -4.04, and it is a seed, not a measurement. For each column, in the lowest band (rows 8 to 28), take the median `log(R/G)` minus the median `log(B/G)`, a number that grows as the sky turns orange, and smooth it over 25 columns. In the frame at -7.05: the leftmost 300 columns sit at -0.411 with a robust spread (1.4826 times the median absolute deviation) of 0.034 and a total range of -0.466 to -0.333. Columns from 534 to the right-hand edge are an unbroken run more than 0.15 above that baseline (4.4 robust spreads, above the left side's own whole range of 0.133); the run's mean excess over columns 540 to 799 is 0.229. Rounded outward to a multiple of ten: **columns 530 to 800**, a third of the frame (270 of 800 columns). Sensitivity: a threshold of +0.10 starts the unbroken run at 520, +0.20 gives a first column at 549 (the run then breaks at 709, a spread of the orange, not a different edge), so 530 is robust to about 20 columns. In the frame at -4.04 no unbroken run reaches the edge at +0.15 (the mean excess over columns 540 to 799 is already 0.097), and the exclusion applies there anyway, because the rule is the sun, not the frame: below -4 every band drops those columns. Excluded columns are counted per band, not filled.

What the exclusion did to the one frame below -6, for the record: the lowest band's `log_rg` contrast is 0.097 with the dome out and 0.110 with it in (and `log_bg` -0.122 against -0.135). It is a small move, because the reference band at the same columns turns orange too, so the contrast already cancels most of what the city light adds. The dome matters most for absolute colour, which tier A does not score; the exclusion is cheap insurance for the contrasts, not a large correction. Its price is a step in which columns are read at the -4 threshold: a frame at -3.9 and one at -4.1 sample different columns, which the file records through `light_dome_excluded`.

**The real run (WHTM1, 2026-10-10, no 2026-10-11 frames yet).** Eight frames, no sidecars (that evening was collected by a one-off loop). Four fall inside the default window and are used; three are above +6 and one is below -6. Lowest-band contrast (rows 8 to 28 minus the reference), by sun elevation: +5.2 degrees `log_rg` 0.013, `log_bg` -0.023; +2.3 degrees 0.144 and -0.206; -0.8 degrees 0.023 and -0.090; -4.0 degrees -0.032 and -0.018 (dome excluded). No band was missing and no pixel was saturated or too dark in any kept frame. One overcast evening, four frames: this shows the pipeline runs on real frames and gives sensible numbers (a warm low band at +2.3, flattening and turning cool as the sun goes down); it says nothing about repeatability, which is gate G1.

**Rejected alternatives:**

- **Degree bands.** Up to 20 degrees (never in frame), and 2 to 5 degrees (their rows move by up to half at every refit). The conductor's rejection, kept.
- **Clipping a band at the frame edge instead of dropping the column.** It would make the band mean different rows in different columns; a whole-footprint rule is easier to count and to explain.
- **Filling a missing band** from its neighbours or from the previous frame. Never: a missing band is data about the evening.
- **Logs of the encoded codes** (no linearisation). The invariance test's positive control shows the codes' log ratio moves by about 0.3 under a gain of 2 where linear light moves it by 0.69, so a per-channel gain would not cancel and exposure would leak into every contrast.
- **Mean in place of median.** A tenth of a band's pixels off colour (a cloud edge, a lamp) moves a mean by 0.03; the median does not move at all (a test pins it).
- **Reading the sun elevation from a sidecar.** The first evening has none, and the observation should not depend on what the collector wrote; the name carries the instant and `geometry` computes the sun. At the registry's public reference position the sun is about 0.2 degrees lower than at the fit's site position for the same frame (14.43 against 14.65 degrees for the first fitted frame), which is the documented price of publishing at the reference point (`docs/design.md` section 3).
- **Refusing a provisional fit** (the camera-geometry log suggested a refusal). The bands are pixels, so the scale uncertainty does not touch the observation; the flag is recorded in the file, and only the nominal `view_elevation_deg` carries it, labelled.
- **Writing no file when no frame is usable.** The file with `frames: []` and the drop counts is the record of the evening; the exit code (1) is the signal.
- **Fitting the dome from many frames.** There is one frame below -6. When the collector has run for more evenings the seed should be refit and frozen before the first scored evening.

**What broke:**

- The first gradient test passed with a wrong skyline. A linear colour ramp has the same band-to-reference difference at any row shift, so reading every column's bands from a fixed row 200 left the contrasts unchanged. A mutation run caught it; the synthetic frames now have dark terrain below the skyline, and a stepped skyline (150 and 190 rows) in the test that reads each column on its own.
- The invariance cannot hold to 1e-6 through 8-bit codes (one code is about 1 percent of the signal at these levels). The exact test builds the frame in linear light and encodes to unrounded floats on the 0 to 255 scale, which `contrast_profile` accepts alongside `uint8`; the 8-bit path is pinned to 0.03, and the end-to-end JPEG test to 0.05 (a gain of 0.6 in blue leaves low codes where JPEG's own rounding shows).
- A median of a ramp with one-sided outliers moves by half a row step, so the "median, not mean" test uses symmetric outliers. Identical synthetic frames had identical SHA-256 prefixes; each test frame now has its own small gain.
- Mutation checks run during the build (each killed by a named test): skipping the linearisation, inclusive band ends, mean for median, `>` for `>=` at 250, `<` for `<=` at 5, 49 against 50 valid pixels, `<=` for `<` at -4 degrees, dropping the reference subtraction, dropping the zero-channel rule, the window edges, the fit digest, the provisional flag, the fit check, and the per-band totals. One survived by design: a half-row change in the band centre moves the nominal elevation by 0.01 degrees, below the 0.05 the tests hold.
