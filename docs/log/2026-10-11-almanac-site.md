# Almanac site v0

**Decided:** `lastlight site build --ledger-dir DIR --out DIR` turns the sealed ledger into a static site, and `.github/workflows/pages.yml` publishes it (issue #9). The generator is `src/lastlight/publish/` (design section 4's `publish`): `ledger.py` reads, `pages.py` renders, `build.py` writes and scans. The command is a thin wrapper in `commands/site.py`.

- **Privacy gates the build, not just the deploy.** The site is rendered into a staging directory beside `--out`, the repository's own scanner (`lastlight.privacy.scan`) runs over it, and only a clean result replaces `--out`. A finding prints, exits 1 and leaves `--out` as it was, so a leaking site is never on disk where an upload step could find it. The workflow runs `lastlight privacy-scan site` again before uploading; the second scan is cheap and independent of the build's own.
- **"Sealed in time" is a result, never a time.** Each evening is run through `lastlight.seal.verify` at build time, and the page says "Sealed before the evening: verified by `lastlight verify`" or "Not verified" with the reason. An evening that fails is listed and marked but never featured; the home page shows the newest verified one and says when the newest ledger entry did not verify. The reason text goes through the scanner like every page: if it holds anything the scanner rejects the build fails, nothing is stripped.
- **The site reads a forecast loosely, on purpose.** The `Forecast` schema refuses clock times in `notes`, so a sealed, valid forecast cannot leak one, and the issue's "planted clock time in a fixture note" can only reach a page if the reader shows what the file says instead of what the schema allows. It does, and `verify` supplies the verdict. The test edits a sealed forecast's note by hand: the date is then marked "Not verified" (digest mismatch) and the scan stops the build.
- **Paintings are decoded and written again, not copied.** `ledger/YYYY/MM/DD.strip.png` (the conductor's layout: the painting beside its forecast, no top-level `strips/`) goes through Pillow and `render.save_strip`, so the published PNG holds IHDR, IDAT and IEND and nothing else. A missing or unreadable painting becomes a text placeholder and a warning per date, never a failed build; a painting that is a symlink, or sits behind a symlinked directory that leads out of the ledger, counts as missing. No camera image is embedded anywhere; the scoreboard is a placeholder until M2.
- **Axis labels are sun elevation in degrees.** The ticks under each painting come from the forecast's own curve (up to eight, every few columns, at the column centres), with true minus signs; the caption states both axes in degrees. The alt text says the same.
- **No script, no external resource, no timestamp of any kind.** The build never reads the clock, so the same ledger gives the same bytes (a test builds twice and compares). Light and dark palettes are CSS variables with every text pair tested against the WCAG AA ratio.
- **A rebuild may replace only what a build wrote.** `--out` must be absent, empty, or hold an `index.html` carrying this generator's marker; anything else is refused with exit 2 and left alone, because the build removes the old directory (`--out .` must never delete a working tree). A symlink is refused too.
- **The workflow is one job** with a `pages` concurrency group that queues and never cancels a running deploy (a skipped run for a failed seal would otherwise take the group and cancel it), a 10 minute timeout, pinned action SHAs, and two decisions in shell that the tests run against fake `git` and `gh`: a missing `ledger` branch (`git ls-remote --exit-code` status 2) builds the empty-state site, any other failure fails the job so a network error cannot publish an empty site over the real one; a Pages API 404 skips configure, upload and deploy with a notice, any other error fails. The build and both scans always run.

**Rejected alternatives:** a templating dependency (f-strings and `html.escape` are enough for five page shapes, and every value is escaped in one place); rendering the painting from the sealed curve at build time (the picture would then be provably the forecast's, but the conductor's contract has the painting committed beside it and `verify` will check its digest, so the site shows that file); client-side JavaScript for tick labels or copy buttons (not needed, and every script is a new place for a time to leak); showing the timestamp's time as "sealed at ..." (the whole privacy design is against it); one `push` filter per branch (YAML allows one `push` key, so the paths are merged).

**What broke or is worth knowing:**

- **A push to `ledger` cannot start `pages.yml`.** `ledger` is an orphan branch holding no workflow file, a push event runs the workflow file at the pushed commit, and pushes made with `GITHUB_TOKEN` start no runs anyway. The issue's "on push to ledger" trigger is kept (it costs nothing and works if the branch ever carries the file), but the trigger that will actually fire is `workflow_run` on a workflow named `seal`. It fires when the seal run finishes, so it does not matter that the seal's own push used `GITHUB_TOKEN`; it does mean issue #8's workflow must be named `seal`. If #8 names it otherwise, change one line, or have it end with `gh workflow run pages.yml` (which needs `actions: write`).
- A single `push:` key cannot carry a per-branch `paths:` filter, so the one filter lists the generator paths plus `ledger/**`; pushes to `main` never touch `ledger/**` and pushes to `ledger` never touch the generator.
- The first full-gate run failed three network-guard tests: they copy `tests/conftest.py` alone into a throwaway project, and my shared fixture imported a helper at the top. The import is now inside the fixture.
- Ruff's line length applies to HTML and CSS in Python strings. The stylesheet moved to `src/lastlight/publish/style.css` (loaded with `importlib.resources`, as `render/data` is) and the prose in the templates is wrapped.
- Headless Chrome at a 375 px window is not a 375 px layout (it enforces a minimum window width, so the screenshot looked clipped). An iframe of that width shows the real phone layout, which has no horizontal scroll.

**Not covered:** the TSA signature chain (the page says so, in the verify section); thumbnails of public cameras (M2, with the operator attribution design section 3 requires); `docs/ledger.md` (issue #8); a mutation sweep beyond the 11 defects tried by hand (scan off, copy not re-encode, escaping off, unverified shown as verified, featured ignores verification, order, alt, verify ignored, reason hidden, directory guard, install on findings), each of which made a named test fail.
