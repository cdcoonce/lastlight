# Scaffold: package, CLI, offline tests, CI

**Decided:** a uv-managed `src/lastlight` package with `lastlight --version`, a subcommand registry, a test suite that cannot touch the network, and one lean CI job (issue #2).

- **argparse, not typer.** The CLI needs a version flag and subcommands, nothing more. The stdlib keeps the dependency list empty, which keeps `uv sync` and the CI job fast.
- **Auto-discovered registry.** A subcommand is a `Command` in its own module under `lastlight/commands/` that defines `COMMAND`. `lastlight.cli.discover` imports them all. Parallel slices each add a file instead of editing one shared list, so they cannot conflict.
- **The network guard raises `RuntimeError`, not `OSError`.** Code under test that retries or falls back on `OSError` would otherwise swallow the block and pass without its data. Tests that need the network opt in with `@pytest.mark.network`, which is deselected by default.
- **CI pins every action to a commit SHA and uv to an exact version,** and sets `UV_FROZEN` so `uv run` never re-resolves. Public repos burn the account's Actions minutes, so there is one job and no cache step.
- **`/data/` is anchored to the repo root** so a future package data directory is not ignored by accident.

**Rejected alternatives:** typer (a dependency for no gain at this size); a hand-edited import list for subcommands (merge conflicts between slices); `--locked` in CI (the issue asks for `--frozen`; the consequence is below).

**What broke:**

- An in-process `pytester` test could not show the guard lifting for a `network` test, because the outer test's guard was still installed. The marker tests run a separate interpreter instead.
- PyYAML reads the workflow key `on` as the boolean `True`, so the CI contract test looks the trigger block up both ways.
- `uv.lock` carries third-party `upload-time` ISO timestamps. They are PyPI release times, not ours, but the privacy scanner will flag them: it needs an allowlist entry for `uv.lock` with that reason.
- `--frozen` does not detect a stale `uv.lock`. A `uv lock --check` step would; adding one needs a decision, because the issue lists the CI steps exactly.
