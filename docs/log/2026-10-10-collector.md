# Public-camera collector (tier A truth)

**Decided:** `lastlight.cameras` holds the tier A registry (`registry.toml`, loaded and validated by `registry.py`) and the polite collector; `lastlight collect` runs it; two systemd user units and `docs/runbooks/collector.md` are the owner's install path (issue #15). Agents did not install the timer.

- **The sun decides the window, per camera, with no sunset table.** Each camera waits until the sun at its own position falls below the start elevation, polls every interval while it is above the stop elevation, and stops. Only a descending sun opens the window, so a launch in the morning twilight waits for the evening instead of polling through the morning; a launch after dusk polls nothing and still prints its summary line. The wait never oversleeps: the sun cannot fall faster than 15 degrees an hour, so a gap of `degrees * 240` seconds cannot be crossed sooner.
- **Politeness is enforced in the library, not only the CLI.** `CollectorConfig` refuses an interval under 300 s, and `collect` re-validates a config that was edited after construction. Each camera's next poll is due one interval after the previous poll *started*, so retries and slow responses never bring two polls closer than 5 minutes.
- **The HTTP layer, the clock and the archive path are injected.** `Fetch` is a function `(url, headers, timeout) -> Response`; `FakeClock.sleep` advances time. A whole evening, with retries and backoffs, runs in milliseconds with no socket.
- **A frame is named and indexed by its own Last-Modified,** in UTC, and the sidecar records the sun elevation at that instant, not at the fetch. The date folder is the local mean solar date derived from longitude (the convention of `lastlight.geometry`), so an evening that passes UTC midnight stays in one folder.
- **A 200 with no usable Last-Modified, an empty body or a non-JPEG body is an error and saves nothing.** The time is the frame's identity and its sun elevation; guessing it would put wrong numbers into the archive. A repeated 200 with the Last-Modified of a frame already saved is logged `unchanged` and counted with the 304s. A stale 200 (more than 20 minutes old) still updates the validators, so the next poll can be a 304 rather than a re-download.
- **Client errors are not retried** (400, 403, 404, 410). Transient ones are: transport failures, 408, 429 and 5xx, three attempts 20 s apart. The issue says "up to 3 attempts", which this satisfies.
- **The archive refusal looks for a `.git` entry in the path and each ancestor,** so it works before the directory exists, needs no git binary, and sees linked worktrees (a `.git` file). The path is resolved first, so a symlink into a work tree is caught. A test also checks it against real `git init` and `git worktree add`.
- **The unit runs `.venv/bin/lastlight` directly,** not `uv run`: no resolver or network at start, and `uv sync --frozen --no-dev` is the whole install. `Restart=on-failure` with `RestartPreventExitStatus=2`, because exit 2 is a configuration refusal, not a crash.

**Camera positions are interim and use the public reference point.** The operator's pages name the town or landmark (Avondale, North Mountain) and publish no coordinates. The task's privacy rule allows no coordinates other than the reference point in tracked files, and `lastlight privacy-scan` (P003) enforces it, so both registry entries carry the reference point and say so in `position_note`. Sun elevation moves about 0.01 degrees per km, so the collector's window shifts by about a minute at most. The issue asked for approximate public positions; getting them in needs a decision, because they are coordinates other than the reference point and need a reasoned allowlist entry (they are the operator's public locations, not the owner's). The ESMO1 azimuth is a nominal 225, since the issue says only "southwest".

**Checked against the real servers, once each, outside the tests:** both image URLs answer 200 with `image/jpeg`, a quoted ETag and a Last-Modified within a few minutes of the response date; a conditional request with the ETag returns 304 carrying the ETag only (no Last-Modified), which is why a 304 leaves the stored Last-Modified in force. The operator's page text says the image updates every 5 minutes; `docs/design.md` says about 15. Not changed here, because one sample cannot settle it; the first week of `log.jsonl` will.

**Rejected alternatives:** a sleep-until-sunset calculation with `elevation_crossings` (its sweep stops at -8 and +6; the issue's defaults are +8 and -10); polling on a fixed tick for all cameras (a slow retry on one would shift the others and break the per-camera 5-minute floor); saving a frame without a Last-Modified under the fetch time (it would defeat the stale check and mislabel the sun elevation); a signal handler for `systemctl stop` (the log already holds every poll, and frames are written atomically); `requests` or `httpx` (a dependency for one GET).

**What broke:**

- The teeth-check matrix over the whole suite ran at about a minute a row while the machine was heavily loaded, and the tool's 10-minute limit killed it mid-row with a mutant still applied. `git status` showed the one-line change; it was restored from git (everything else was committed first) and the bytecode purged. The spec now runs only the five test files the mutants can affect, which takes a couple of minutes for 46 rows. Run `git status` after any killed mutation run.
- `sed -i` on macOS needs an empty backup suffix; the bare form failed and, being first in an `&&` chain, silently skipped the file written after it. The deploy tests caught the missing service unit.
- The first draft of the missing-Last-Modified test matched only the substring `Last-Modified`, so deleting the missing-header check survived: the unreadable-header check below it produced an error with the same word. The test now matches each reason in full.

**Not built here:** rejection of a frame by its burned-in timestamp (named in `docs/design.md` section 4; it needs the pixels, so it belongs with `observe`), thumbnail publishing, and real camera coordinates (see above). The fixed afternoon start time in the timer unit and the runbook needed two allowlist entries, added here with reasons.

**Next:** `camgeom` (pixel-to-sky calibration from the sun's track), then `observe` (contrast profiles from the archive).
