# Seal retry, missed evenings, and the 60-day rule

**Decided:** the daily seal retries once, in Python; the almanac site says so when an evening has no seal; `docs/ledger.md` documents GitHub's 60-day rule for scheduled workflows (issue #26). The conductor's spec comment on the issue pinned the decisions; this entry records how they landed.

- **The retry is `lastlight.daily.seal_with_retry`, driven by `seal-daily --attempts N --retry-pause SECONDS`** (defaults 1 and 300; the workflow passes `--attempts 2`). The loop takes an injected clock and an injected sleep, so no test waits, and it takes the attempt as a function of "now", so the command hands it a closure over `seal_daily` and tests can fake the attempts at that seam. Only `HrrrError`, `FetchError` (the weather ingest's, in `inputs.http`), `TsaError` and `OSError` are retried. Anything else (`TooLateError`, `ReductionError`, `StripError`, `AlreadySealedError`, `SealVerificationError`, `ValueError`) is raised at once with today's exit code.
- **Never late.** After a transient failure the loop reads the clock, and if that plus the pause reaches `evening_deadline(evening)` (the sun at the horizon at the reference point, now one function that `seal_daily`'s own refusal also uses) it does not pause and raises the failure; stderr says why. Otherwise it pauses and reads the clock again, and that fresh reading is the second attempt's `now_utc`, so a runner that stalled through the pause is refused by the existing late check (exit 3) and seals nothing. The deadline is judged from the clock after the failure, not from the start of the run, because the first attempt may itself have been slow to fail.
- **Exit code and stderr.** The exit code is the last attempt's. With more than one attempt each failure is one line, `seal-daily: attempt 1 of 2 failed: <reason>`, followed by either `pausing 300 seconds before attempt 2 of 2` or `not retrying: <why>`; with one attempt the line is exactly what it was before (`seal-daily: <reason>`). No line holds a clock time or the deadline, only durations.
- **Missed evenings are a reading of the ledger, not a new file.** `lastlight.publish.missed` has `missed_evenings(sealed, through)` (dates from the first sealed evening to `through`, inclusive, with no index row, newest first) and `default_through(now_utc)` (the local mean solar date at the reference point once its deadline has passed, else the day before). `build_site(ledger_dir, out_dir, *, through=None, now_utc=None)` and `lastlight site build --through YYYY-MM-DD` set the date; the clock is read in one place (`build.utc_now`), once per build: it chooses the default `through` and bounds an explicit one.
- **What the site says.** "No forecast was sealed for D." and nothing else, dates only. Every missed evening is an entry in the archive, interleaved with the sealed ones by date so a gap shows where it is. The home page leads with the statement for the newest missed evening only when that evening is newer than every sealed one (it follows the heading, before everything else), and the newest verified painting is still featured under its own date. A missed evening has no page, no link and no painting, so the page set and the counts in `BuildReport` and the command summary are unchanged; `BuildReport` gains `missed` and `through`, and the command summary appends "N missed evenings listed" only when there are some. An evening with an index row is sealed even if it does not verify (a late seal is listed and marked, not called missed), and an empty ledger keeps its empty state.
- **The 60-day rule is in `docs/ledger.md`,** with links to GitHub's `schedule` and enable/disable pages, a paraphrase of the rule, the re-enable steps (the Actions tab, or `gh workflow enable seal.yml -R cdcoonce/lastlight`), and the build-board sentence (sealed, retried or missed, by hand, until scoring exists). GitHub's pages do not define repository activity, so whether the Actions bot's pushes to `ledger` count, and whether activity off the default branch counts, is written down as unverified, with the safe assumption that only a person's commit to `main` counts.

**Rejected alternatives:**

- Retrying every failure: a deterministic failure cannot heal, and the pause would cost billed minutes for nothing.
- A YAML-level retry (a retry action, `continue-on-error`, a second job): the issue rules it out and no test can reach it. A test pins that the workflow has none.
- Running `pages.yml` after a failed seal as well, so the site shows the miss at once: the seal runs before sunset, so by the deadline rule that build could not yet call the evening missed. The next day's build shows it and costs no extra billed minutes.
- A page per missed evening: it would add pages that carry no data, and the existing page-set and link tests describe the site as one page per sealed date.

**What broke or is worth knowing:**

- **The existing site tests read the real clock now.** With no `--through`, the default depends on the day the build runs, and every fixture ledger is dated mid-October 2026, so once the real date passes them the fixtures grow trailing missed evenings and those tests would see a different home page and archive. The new markup was therefore built not to disturb them: missed entries are `li.missed`, not `li.evening`; the lead is `p.missed`, not `p.notice`; no new page, link, image or warning. This was measured, not just reasoned: the existing site, build, command, ledger and pages-workflow tests were run under a throwaway pytest plugin that pins `build.utc_now` a year ahead (hundreds of trailing missed evenings), and all 142 passed.
- **Twelve usage-error tests passed before the options existed.** The first draft of the bad `--attempts`, `--retry-pause` and `--through` tests asserted only that the option name was in stderr, which argparse also prints for "unrecognized arguments". They now require `argument --attempts:` (the option's own check). Of the 111 tests in the red commit, 15 passed with throwaway stubs standing in for the missing names; after that fix the only passes left are three guards that pin things that must stay true (no clock time or position in the guide, the signature caveat untouched, no retry in the workflow YAML).
- **A mutation sweep of 23 injected defects** (the deadline comparison, retrying a non-transient failure, retrying past the last attempt, the transient set, a stale `now`, no sleep, the deadline judged from the start, the default `--attempts`, the real sleep not wired, the workflow flag, the `through` boundary, the default `through`, the first-seal bound, `through` dropped, an unverified evening called missed, the lead without the newer-than-every-seal check, the oldest missed evening as the lead, the archive hiding missed evenings, the summary) found one gap: nothing checked that the lead's pointer to the painting below is dropped when no evening verified. A test now does. Two mutants survived as equivalent (`range(days)` for `range(days + 1)`, because the extra date is the sealed first one, and a redundant empty-ledger guard).
- **`OutsideGridError` is a `HrrrError`,** so the pinned set retries it although it cannot heal. It cannot happen at the fixed reference point, and the cost would be one pause.
- **`lastlight.daily` loads the GRIB library,** which the site build has no use for, so `publish.missed` computes the deadline from `geometry` itself; a test pins that it agrees with `daily.evening_deadline` at the boundary.
- **The workflow test lives in `tests/test_seal_retry.py`,** not in `test_seal_workflow.py`: it parses the real `seal-daily` line with the command's own parser, so a flag typo in the YAML fails a test.

**Known limits:** the job's limit stays at 15 minutes (`test_seal_workflow.py` pins it). Two attempts and one 5-minute pause fit, but a first attempt that times out on every request of a slow bucket can run for many minutes (the HTTP timeout is 60 seconds per request) and leave too little for the second; the job is then cut off and fails visibly, no worse than before. Whether the bot's own pushes keep the schedule alive is unverified, and the first real retry will only be seen in a run log.

**Fix round (reviewer: FIX FIRST).** One survivor is killed: a test now pins that the archive explains missed evenings only when some are missed. One copy defect is fixed: the home lead said the newest sealed evening is shown below even when that evening did not verify and an older one was shown, so `_missed_lead` now says what is true in each of the three states (newest verified and shown, newest not verified with an older one shown, nothing verified), with teeth rows for both directions. A `--through` later than the newest evening whose deadline has passed is now refused (`BuildError`; exit 2 from the command, nothing written) instead of listing an evening that has not happened as missed, with rows for the bound and its edge; the build therefore reads the clock on every run, and `test_site_missed.py` pins that clock so its explicit `through` dates stay valid. The workflow pin stays in `tests/test_seal_retry.py`, where it parses the real line.
