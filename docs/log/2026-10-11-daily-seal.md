# Daily painting and the scheduled seal

**Decided:** every day a GitHub Actions workflow named `seal` paints the coming Phoenix evening from HRRR, seals the forecast and its painting, verifies the seal and commits it to an orphan `ledger` branch (issue #8). `lastlight forecast` paints an evening by hand, `lastlight seal --strip` seals it, `lastlight seal-daily` does both for the scheduled run, and `lastlight verify` now checks the painting too. How anyone verifies a day is in `docs/ledger.md`.

- **One root for the ledger.** The `ledger` branch's root holds only `ledger/`, in the existing seal layout, with the painting beside its forecast as `ledger/YYYY/MM/DD.strip.png`. `main` never carries daily data. The almanac slice reads exactly this layout.
- **The painting is sealed.** `Forecast` gains `strip_sha256`, the SHA-256 of the PNG, so the one timestamp covers the numbers and the picture. It is required but may be null, and the canonical form always writes it (`"strip_sha256":null` when there is none). `schema_version` stays 1 because nothing has been sealed yet. `seal` takes the PNG and refuses one that is not the forecast's, or that the privacy scanner's image rules would flag (the ledger is append-only, so a sealed leak could not be removed); `verify` checks that the PNG exists and hashes to the field, fails on a changed or missing one, fails on a PNG that sits beside a forecast that names none, and says `PASS (strip verified)`.
- **The v0 reduction has its own module, `lastlight.atmosphere`.** `reduce_transect(samples, evening)` returns the renderer's `Atmosphere` plus the pieces and the sealed notes. It imports no GRIB library, takes no clock and no files, so the G0 spread study (#10) can call it per archived date. AOD is the unweighted transect mean of HRRR `AOTK` plus a fixed 0.06 background; ozone is looked up by the evening's month; precipitable water is averaged and recorded but not passed on (the renderer has no water term); cloud cover, base and top are summarised in the notes and not rendered; `AOTK` or `LCDC` missing everywhere is an error, because a forecast painted from nothing would read as clean, clear air.
- **Ozone table: NASA SBUV, not OMI.** `OZONE_DU_BY_MONTH` is the monthly mean of NASA Goddard's merged SBUV total ozone zonal means (MOD v8.7) for the 30 to 35 N band over 2005 to 2024, rounded to 0.1 DU: 286.6, 295.0, 307.2, 317.5, 315.0, 303.2, 295.6, 289.7, 282.4, 272.4, 270.5, 276.9 (January to December). NASA publishes it as plain text in 5 degree bands, so the numbers are read, not typed. The 20 source rows are committed in `tests/fixtures/ozone/`, a test recomputes the table from them, and `tools/make_ozone_climatology.py` rebuilds both. August 2022 has no data in the band and is left out of that month's mean.
- **Vividness v0 is a named placeholder.** Mean 0.45 minus 0.30 times low cloud cover plus 0.25 times aerosol optical depth over 0.4 (capped), sd 0.25. The sd is a quarter of the scale on each side, so it says little either way, and the rule's name goes into the sealed notes.
- **The evening defaults to the local mean solar date at the reference point** (`cameras.archive.evening_date`), so a run in the UTC afternoon seals the evening that is coming. A test walks the year and requires the cron hour to land at least two hours before the earliest sunset.
- **Idempotent and never late, in Python.** `seal_daily` checks for an existing seal first (nothing painted, no timestamp requested, nothing written), then refuses if the sun is already at the horizon at the reference point (exit 3, "never back-filled"), then paints, seals and verifies. "Late" means the evening's sunset instant has passed, not that the sun is below the horizon right now: a run in the small hours of the night before is early, not late. An existing seal is verified before a rerun reports "already sealed"; one that no longer verifies is an error (exit 1), not a quiet success.
- **The git plumbing is Python too (`lastlight.ledger_branch`, command `ledger-branch open|publish`).** It is tested against a real local bare remote: an orphan is started only when the remote answers that the branch is absent (an unreachable remote is an error, never a second ledger), the branch root holds only `ledger/` and has no parent, only `ledger/` is staged, the message is `seal: YYYY-MM-DD <digest[:12]>`, the author is the Actions bot, nothing is forced, and the token is passed to the push alone as an HTTP header and scrubbed from errors. Starting an orphan uses `git worktree add --orphan` (git 2.42 or newer; the `ubuntu-latest` image should ship a newer git, which could not be checked from here).
- **The workflow is one job, `permissions: contents: write` only.** It is named `seal` because the almanac's site deploy runs on `workflow_run` of that name. It checks out `main` without leaving credentials behind, opens the ledger worktree, runs `seal-daily`, scans the whole ledger directory with `privacy-scan` (not only the new files: a past leak should block every later seal), and publishes. Runs queue (`cancel-in-progress: false`), actions are pinned to the SHAs `ci.yml` uses, and a test pins the structure and the step order. Any non-zero exit fails the job.

**Rejected alternatives:**

- A separate top-level `strips/` tree, as the issue wrote it: it splits one day's sealed artifacts across two roots.
- A strip with no seal: the claim "painted before it happens" would cover only the numbers.
- A `strip_sha256` that defaults to null and is left out of the canonical form when null: a code path that forgot the painting would silently seal a forecast without one.
- OMI or TOMS for ozone: OMI is gridded behind an Earthdata login, the TOMS zonal tables end in 2005, CAMS is licensed rather than public domain, and inventing numbers was ruled out. The SBUV record is plain text, current, and NASA's.
- An explicit `gh workflow run` of the site build from the seal job (the first draft, and the brief's first version): more privilege (`actions: write`) for the same effect, and it would deploy twice alongside the site's `workflow_run` trigger. The seal job no longer knows the site exists.
- Git steps in YAML shell: untestable until after the merge.
- Re-recording the TSA fixture when the canonical form changed: see below.

**What broke:**

- **The recorded TSA response covers the old canonical bytes.** Adding `strip_sha256` changed every canonical form, so the real response recorded in `tests/fixtures/seal/stub-forecast.tsr` no longer matched `STUB_DIGEST`. `recorded_tsr()` now re-points its fixed-width imprint at the current digest (the same in-place patch `make_tsr` already used for dates), and `recorded_response()` is the file as the TSA sent it. Every seal test kept its assertion. The golden canonical bytes gained `"strip_sha256":null,`, and the TSA request test now says only the structure around the digest was what the authority accepted.
- **`fetch_fields` threw away the raw bytes** the forecast needs to record "every input's digest", so `HrrrFields` gained `digests` (SHA-256 of each raw GRIB message), computed from the same bytes that were decoded. Two tests for it landed with the implementation, not in the red commit.
- **A first draft of `forecast` without `--strip` still named a strip.** `paint` always made one; the test for a null `strip_sha256` caught it, and `paint` now takes `with_strip`.
- **One branch cannot be checked out in two worktrees of the same repository,** so the tests that race two publishers use two clones, as two runners would. The workflow has one worktree.
- **Water vapour looks like a position.** Precipitable water of 31 to 37 kg m-2 is a decimal in the Arizona latitude range, next to a second decimal it could read as a coordinate pair to P003. The notes print everything but aerosol and water as whole numbers, and a test sweeps values through the dangerous range.
- **The system `curl` on this Mac could not fetch the NASA file** (a TLS handshake failure in LibreSSL); Python's `urllib` could, and the tool uses that.
- **The conductor changed the plan mid-build:** the workflow no longer dispatches the site build, `actions: write` and the `pushed` output the dispatch step needed were removed, and the layout is documented in `docs/design.md` section 4.
- A mutation sweep of 18 injected defects (late boundary, idempotence, the post-seal check, the strip checks, the schema default, the AOD and ozone terms, staging everything, a forced push, the token on other git calls, an orphan started on an unreachable remote, the default evening, the vividness sign, the input digests) was caught by a test each. One mutant, a token on a non-push call, first survived because it used a different token than the test checks; the test is right, the mutant was wrong.

**Review round (a hostile mutation sweep of 94 injected defects found 13 that no test could see):**

- **Tests that could not fail now can.** The late-seal boundary is pinned at one second, not two; the `ledger-branch publish` command is tested with `GITHUB_TOKEN` set and the encoded header must appear on the push call and no other (a decoy `GH_TOKEN` must not be used); the workflow test now walks the whole parsed YAML so the token appears nowhere but the publish step's `env`; the AOD and cloud tests use skewed data so a mean cannot pass for a median or a maximum, and the exact cloud and closing sentences of the sealed notes are asserted; the painting's vividness must equal the rule applied to the reduction's low cloud and AOD; the token-scrub test runs a git that echoes its arguments, because real git never prints the header.
- **`seal` accepts only a PNG as the strip.** The image scanner goes by the bytes, so a metadata-free JPEG or WebP passed it and would have been sealed as `DD.strip.png`. The PNG signature is now checked first.
- **`code_sha` is the commit of the checkout that ran.** `GITHUB_SHA` is no longer read: on a manual dispatch from another branch it names that branch's commit while the job runs `main`. `LASTLIGHT_CODE_SHA` still overrides.
- **The vividness clamp is gone.** The mean cannot leave 0.15 to 0.70, so the clamp could never act; a test pins both ends so a weight change that left the scale fails instead of being clipped.
- **The recorded timestamp keeps an outside check.** One test reads the raw recorded response and requires its imprint to be the SHA-256 of the stub's canonical bytes before `strip_sha256` existed, written out by hand; another requires the canonicaliser to produce those bytes plus the null member.
- **Local runs no longer dirty `main`:** `/ledger/`, `/ledger-wt/`, `/forecast.json` and `/strip.png` are ignored, checked against a real repository.
- **The rig is committed:** `tests/teeth/daily-seal*.json` (five specs, 103 mutants and 5 declared-inert controls, paths relative to the spec). Run one from the repository root with the workshop `detector-teeth-check` script, for example `python3 <skill>/scripts/teeth_check.py tests/teeth/daily-seal.json`; `--check-anchors` resolves every anchor without running anything. The specs are split so each run fits in a few minutes.

**Known limits:** the workflow has not run, and it depends on `git worktree add --orphan` being available on the runner; its first real run is the post-merge dispatch. A dispatch outside the sealing window refuses (exit 3), by design. A push that races another writer is rejected and the job fails visibly; a rerun is safe because it is idempotent. The AOD is an unweighted mean along the transect, cloud is not rendered, HRRR cloud heights are geopotential metres of unsettled reference, the vividness rule is a placeholder, one timestamp authority is a single point of failure, and `verify` still does not validate the timestamp's signature chain (issue #25).
